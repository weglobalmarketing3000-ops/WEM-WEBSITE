Collection by TikTok Warehouse Handoff: The Cutoff, Scan and Exception SOP

Control the warehouse moment when an order moves from seller responsibility into a verified carrier handoff.

WE Marketing Team · Oct 12, 2026 · 15 min read

Direct answer: treat Collection by TikTok handoff as a controlled batch release, not as a driver arrival. Lock a warehouse cutoff, pick and pack against one package list, use the official CBT label, stage CBT parcels separately, reconcile the physical count to the scan record, and release the batch only to the designated CBT pickup carrier. A manifest or in-app scan can create useful dispatch evidence, but it does not replace the physical handoff or the carrier acceptance scan.

Collection by TikTok combines pickup and last-mile services under TikTok Shipping for eligible U.S. sellers. The current overview says sellers can keep their existing warehouses while using pickup in supported areas. That convenience does not remove warehouse responsibility. Before pickup, the seller still owns SKU accuracy, packaging, label quality, origin integrity, readiness, and exception communication.

Define the handoff boundary before writing the SOP

The operating boundary has three different records. First, the warehouse creates an order and package record. Second, a TikTok Manifest or in-app scan may record that a prepared batch exists. Third, the designated carrier physically receives and scans the parcels. These events are related, but they are not interchangeable. The shipping requirements warn sellers not to use manifest or scan functions to misrepresent actual handoff activity, and they monitor unusually long gaps between Awaiting Collection and In Transit.

Your warehouse SOP should therefore identify the exact release event. A supervisor signs only after the package count, warehouse origin, labels, scan evidence and pickup carrier all match. The exception owner then watches for the first carrier movement. If it does not appear within the operating threshold, the batch becomes an active exception rather than an assumed success.

Build one cutoff clock backward from pickup

The current CBT warehouse SOP describes a typical daily pickup window of 10:00 to 18:00 local time and says sellers should have packages ready before pickup. It also states that same-day pickup cancellations must be communicated directly to carriers by 9:00 AM local time. Treat these as current official reference points, not as a promise for every warehouse. Your assigned provider, local schedule, holidays and account arrangement remain controlling.

Set a warehouse-specific pickup time and work backward. A practical control schedule has five gates: order cutoff, pick completion, pack completion, label and scan reconciliation, and dock release. Add buffer between each gate. If the carrier comes early, the batch is ready. If volume spikes, the team can stop adding orders rather than mixing incomplete parcels into a released batch.

Pick and pack for auditability

Use a package-level worklist, not only an order total. Each row should contain order ID, package ID, SKU and variant, quantity, warehouse, label ID, actual packed weight, dimensions, special handling status and final staging zone. One person can pick and another can verify. For high-risk SKUs, photograph the packed contents before sealing when privacy and internal policy permit.

Packaging has to protect the product and support the carrier path. The shipping requirements place responsibility on sellers using CBT for secure packing and compliant labels. The CBT warehouse SOP expects labels to be clear, legible, securely attached to a flat surface, and scannable without folds, wrinkles or obstruction. A label that exists but cannot scan is an exception, not a completed package.

Keep CBT parcels in a separate physical lane

The CBT warehouse SOP requires sellers to sort and pack CBT parcels separately and have them collected by the CBT pickup carrier. It specifically warns against handing CBT parcels directly to a last-mile delivery carrier. The label may name a downstream network, but the warehouse release path remains the assigned CBT pickup flow.

Create a clearly marked staging area for each pickup date and warehouse. Do not mix CBT with Seller Shipping, other TikTok Shipping handoffs or returns. Use a visible batch card that shows package count, manifest ID when used, cutoff time, assigned carrier and exception count. Physical separation makes the final count faster and prevents a busy dock from releasing the right package to the wrong network.

Use scans as evidence, not theater

For invited sellers, TikTok Manifest can group packages from the same warehouse. The official guide says the team should print the manifest, scan its QR code in the Seller App, verify that the recognized package list matches the physical batch, take the required photo and then hand the parcels to the carrier promptly. TikTok Shop retains the first recorded manifest scan time, so rescanning does not replace an earlier time.

A scan should happen only when every included package is ready for handoff. If the count is wrong, stop and reconcile. If a label was canceled and replaced, the prior manifest scan does not carry over to the new label. Create the correct record again. Never scan unfinished packages merely to improve a metric. The shipping requirements explicitly prohibit misuse of manifest or in-app scan events.

Record the physical handoff separately

At pickup, verify the service provider and driver route against the assigned CBT information. Count the parcels with the driver or approved process, record the time and retain the available receipt, photo or dock log. The supervisor should be able to answer four questions later: which packages left, from which warehouse, with which carrier, and at what time.

After release, monitor the first logistics movement. A scan record may qualify for dispatch treatment in some eligible cases, but it does not remove the need for physical movement. Use a next-check deadline. If the package remains Awaiting Collection or lacks expected movement, open an exception with the provider while the batch evidence is still easy to retrieve.

Run one exception ledger

A warehouse chat can coordinate, but it is not the system of record. The exception ledger should name the package, batch, failure type, discovery time, current custody, evidence, owner, next deadline and resolution. Use a short controlled taxonomy: late order, short pick, wrong SKU, packaging failure, unreadable label, scan mismatch, missed pickup, wrong carrier, wrong warehouse, delayed first movement, failed delivery and return.

For a missed pickup, keep the batch controlled, contact the provider and record the new plan. For a labeling or packaging failure, remove the package from the release count, correct it and repeat verification. For a count mismatch, stop the dock handoff until the physical and digital lists agree. For a wrong carrier or origin, do not improvise an offline route. Rebuild the correct CBT path.

Handle returns as a new warehouse event

The CBT SOP includes a failed-delivery and return process. When a parcel returns, check it into a separate return area, photograph the exterior condition, verify the package and item identity, inspect the product, record the reason and decide whether it can return to sellable inventory. Do not quietly place it back into stock. The original shipment record and the return disposition should remain linked.

Use return patterns to improve the outbound SOP. Repeated address issues, label damage, packaging failures or SKU mistakes should create a named corrective action. The goal is not merely to close exceptions; it is to reduce how often the same failure reaches the dock.

Daily CBT warehouse review

  1. Confirm today's warehouse, pickup provider and expected window.
  2. Lock the order cutoff and package list.
  3. Review open exceptions from the prior batch.
  4. Verify pick, pack, weight, dimensions and labels.
  5. Stage CBT parcels separately by batch.
  6. Reconcile scan count, package count and photos.
  7. Release only to the designated CBT pickup carrier.
  8. Record the physical handoff and first movement.
  9. Escalate missed pickup or status gaps by owner and deadline.
  10. Review returns and update the corrective-action list.

The smallest useful action today

Choose one warehouse and one pickup batch. Write the five gate times, print a package-level checklist, create a CBT-only staging zone and assign one handoff supervisor. Reconcile the physical package count to the scan record and keep a signed release record. The next day, review every package that lacks expected movement before expanding the process.

Common questions

Does a TikTok Manifest scan prove that the carrier received every package?

No. The official guide says a manifest scan records the batch and may qualify for dispatch treatment on eligible orders, but it does not replace physical handoff or the carrier acceptance scan.

Can CBT parcels be handed directly to the last-mile carrier named on the label?

No. The CBT warehouse SOP says CBT parcels must be separated and handed only to the pickup carrier designated by CBT, not directly to a last-mile carrier.

What is the same-day CBT pickup cancellation cutoff?

The current CBT warehouse SOP says same-day cancellations must be communicated directly to the carrier by 9:00 AM local time. Confirm the current provider instructions before acting.

Can one TikTok Manifest contain packages from multiple warehouses?

No. The manifest guide requires one warehouse per manifest. Filter by warehouse and create a separate manifest for each physical origin.

What should the warehouse do when a package fails label or packaging inspection?

Remove it from the handoff batch, record the exception, reprint a clear official label or repack the parcel, then repeat verification before release.

What is the smallest useful CBT control test?

Run one pickup batch with a locked cutoff, independent package count, scan evidence, signed physical handoff record and next-day exception review. Repair any mismatch before expanding volume.

Collection by TikTok 仓库交接：截单、扫描与异常处理 SOP

把订单从卖家仓责任转移到承运商之前的最后一个小时，做成可核验的交接控制。

WE Marketing Team · 2026 年 10 月 12 日 · 15 分钟阅读

直接答案：Collection by TikTok 的仓库交接不能只理解为“司机来了，把货拿走”。它应该是一套受控的 Batch Release：先锁定仓库截单时间；按照同一份包裹清单完成拣货与打包；使用官方 CBT 面单；把 CBT 包裹独立分区；让实体数量、扫描记录与批次照片一致；最后只交给 CBT 指定的 Pickup Carrier。Manifest 或 In-App Scan 可以形成发货证据，但不能替代实体交接，也不能替代承运商的 Acceptance Scan。

Collection by TikTok 把 Pickup 与 Last-mile Service 组合在 TikTok Shipping 体系内，让符合条件的美国卖家继续使用现有仓库。对中国品牌或跨境团队来说，便利并不等于责任转移。司机取件之前，SKU 准确性、包装、面单、出库仓、批次准备度与异常沟通仍由卖家仓负责。

先定义“交接完成”，再写 SOP

仓库里至少有三种不同记录。第一，系统生成 Order 与 Package Record。第二，TikTok Manifest 或 In-App Scan 记录一个已经准备好的批次。第三，指定承运商实体接收并扫描包裹。这三件事互相关联，但不能互相替代。Customer Order Shipping Requirements 明确禁止利用 Manifest 或扫描功能虚构实际交接，平台也会关注 Awaiting Collection 与 In Transit 之间异常过长的间隔。

因此，SOP 必须写清楚真正的 Release Event。只有当包裹数量、出库仓、面单、扫描证据与 Pickup Carrier 全部一致，主管才能签字放行。放行后还要继续观察第一条承运商轨迹；如果在内部设定时限内没有出现，批次应自动进入 Exception Ledger，而不是被默认成已成功发货。

从 Pickup Time 倒推唯一的截单时钟

当前 CBT Warehouse Operations SOP 提到，日常取件窗口通常是当地时间 10:00 至 18:00，并要求卖家仓在取件前准备好包裹；当天取消取件，则应在当地时间上午 9:00 前直接通知承运商。团队应把这些当成当前官方参考，而不是所有仓库的固定承诺。最终仍以账号实际分配的服务商、当地排期、节假日与当前通知为准。

为每个 Warehouse 设定实际 Pickup Time，再向前倒推五道闸门：Order Cutoff、Pick Complete、Pack Complete、Label and Scan Reconciliation、Dock Release。每道闸门之间保留缓冲。订单晚于 Cutoff，就进入下一个受控批次，而不是临时塞进已经扫描的包裹堆。

闸门必须保留的证据停止条件
截单按仓库与 Pickup Date 冻结包裹清单迟到订单进入下一批次
拣货SKU、Variant、数量与订单一致缺货或替换商品必须隔离
打包防护、重量、尺寸与特殊处理标识不安全或数据不准就重新包装
面单与扫描官方清晰面单、批次数量、扫描结果、照片数量或条码不一致就停止放行
实体交接指定承运商、时间、包裹数与仓库记录承运商错误或证据缺失就停止放行

让拣货与打包可以被追溯

不要只保留订单总数，要建立 Package-level Worklist。每一行至少包括 Order ID、Package ID、SKU 与 Variant、数量、Warehouse、Label ID、打包后的实际重量与尺寸、特殊处理状态、最终 Staging Zone。可以由一人拣货、另一人复核；对于高风险 SKU，在符合隐私与内部政策的前提下，可在封箱前保存内容物照片。

Customer Order Shipping Requirements 把安全包装与合规面单的责任放在使用 CBT 的卖家身上。CBT Warehouse SOP 进一步要求面单清晰可读、牢固贴在包裹平面，条码不能被折痕、褶皱或遮挡影响。面单已经打印但无法扫描，仍然是异常包裹，不能算完成。

为 CBT 建立独立的实体分区

官方 CBT 仓库 SOP 要求卖家把 CBT 包裹单独分拣打包，并交给 CBT Pickup Carrier。它还明确提醒，不能绕过 Pickup Carrier，直接把 CBT 包裹交给面单所显示的末端承运商。即使面单上出现下游网络，仓库出库路径仍然要走被分配的 CBT 取件流程。

仓库应按 Pickup Date 与 Warehouse 建立清晰标记的 Staging Zone，不能与 Seller Shipping、其他 TikTok Shipping 批次或退件混放。每个批次挂一张 Batch Card，写明 Package Count、Manifest ID、Cutoff Time、Assigned Carrier 与 Exception Count。实体分区能加快最终复核，也能避免忙碌 Dock 把正确包裹交给错误网络。

扫描是证据，不是为了做出“已发货”的样子

对获得权限的卖家，TikTok Manifest 可以把同一仓库的包裹组成批次。官方指南要求团队打印 Manifest，在 Seller App 扫描 QR Code，确认系统识别的 Package List 与实体批次一致，完成批次照片，再迅速交给承运商。TikTok Shop 使用第一次 Manifest Scan Time，重复扫描不会覆盖最初时间。

只有当批次内每个包裹都真正准备好交接时才扫描。数量不一致就立即停止并逐件复核。取消旧面单并购买新面单后，旧的 Manifest Scan 不会自动转移到新面单，需要重新建立正确记录。不能为了时效指标扫描尚未完成的包裹，官方 Shipping Requirements 明确禁止滥用 Manifest 或 In-App Scan。

实体交接必须单独留证

Pickup 到达时，先把服务商与 Driver Route 和账号分配的 CBT 信息核对。按照批准流程与司机复核包裹数量，记录时间，并保存可获得的 Receipt、照片或 Dock Log。以后复盘时，主管必须能回答四个问题：哪些 Package 离开了、从哪个 Warehouse 离开、交给了哪个 Carrier、具体时间是什么。

交接后继续监控第一条 Logistics Movement。部分符合条件的扫描记录可能用于判断 Dispatch SLA，但这不意味着包裹已经发生实体移动。为批次设置 Next-check Deadline；如果包裹长时间停留在 Awaiting Collection，或者没有预期轨迹，应在证据仍容易调取时立刻联系 Provider 并打开异常。

异常必须进入同一张 Ledger

仓库群聊可以协调，但不能成为 System of Record。Exception Ledger 至少包括 Package、Batch、Failure Type、发现时间、当前 Custody、证据、Owner、下一个 Deadline 与 Resolution。建议使用固定分类：Late Order、Short Pick、Wrong SKU、Packaging Failure、Unreadable Label、Scan Mismatch、Missed Pickup、Wrong Carrier、Wrong Warehouse、Delayed First Movement、Failed Delivery、Return。

Missed Pickup 时，保持批次受控，联系 Provider 并记录新计划；面单或包装失败时，从 Release Count 中移除，修复后重新核验；数量不一致时，停止 Dock Handoff，直到实体与数字清单完全一致；Wrong Carrier 或 Wrong Origin 时，不要临时寻找 Offline Route，而要重建正确 CBT 路径。

退件是一次新的仓库事件

CBT SOP 包含 Failed Delivery and Return Process。退件回仓时，应进入独立 Return Zone，登记到仓时间，拍摄外包装状态，核对 Package 与 Item Identity，检查商品情况，记录退件原因，并决定能否回到 Sellable Inventory。不能不留记录就直接放回库存。原 Shipment Record 与 Return Disposition 必须保持关联。

退件模式还要反向修复出库 SOP。如果地址问题、面单损坏、包装失败或 SKU 错误反复出现，就创建明确的 Corrective Action 与 Owner。目标不是只把异常关闭，而是减少同类问题再次走到 Dock。

每日 CBT 仓库复盘

  1. 确认当天 Warehouse、Pickup Provider 与预计窗口。
  2. 锁定 Order Cutoff 与 Package List。
  3. 检查上一批次尚未关闭的异常。
  4. 复核拣货、打包、重量、尺寸与面单。
  5. 按批次独立摆放 CBT 包裹。
  6. 核对扫描数、实体包裹数与照片。
  7. 只交给指定 CBT Pickup Carrier。
  8. 记录实体交接与第一条承运商轨迹。
  9. 按 Owner 与 Deadline 升级 Missed Pickup 或状态缺口。
  10. 复盘退件，并更新 Corrective Action List。

今天就做的最小动作

选择一个 Warehouse 和一个 Pickup Batch，写出五道闸门的时间，打印 Package-level Checklist，建立 CBT-only Staging Zone，并指定一名 Handoff Supervisor。让实体包裹数与扫描记录完全一致，保存签字放行证据；第二天先检查所有没有预期轨迹的包裹，再决定是否扩大批次。

常见问题

TikTok Manifest 扫描能证明承运商已收到全部包裹吗？

不能。官方说明指出，Manifest Scan 会记录批次，并可能在符合条件的订单中用于判断发货时效，但它不替代实体交接，也不替代承运商的 Acceptance Scan。

CBT 包裹可以直接交给面单上的末端承运商吗？

不可以。CBT 仓库 SOP 要求包裹独立分区，并且只能交给 CBT 指定的 Pickup Carrier，不能绕过取件服务商直接交给末端承运商。

当天取消 CBT 取件的截点是什么？

当前 CBT 仓库 SOP 说明，当天取消必须在当地时间上午 9:00 前直接通知承运商。实际操作前仍要核对当前服务商要求。

一个 TikTok Manifest 能包含多个仓库的包裹吗？

不能。Manifest 指南要求每个 Manifest 只对应一个仓库。必须先按 Warehouse 过滤，再为每个实体出库点分别创建批次。

包裹没有通过面单或包装检查时怎么办？

先从交接批次中隔离，登记异常，重新打印清晰的官方面单或重新包装，然后重新核验后才能放行。

最小可执行的 CBT 控制测试是什么？

先跑一个 Pickup Batch：锁定截单时间，独立复核包裹数，保存扫描证据和实体交接记录，并在次日复盘异常；任何数量或状态不一致都先修复，再扩大批次。
